HOW PRIVILEGES WORK

Role-Based Access Control Architecture

When you sign in, Keycloak mints an RS256 JWT access token. The resource API at http://localhost:5000 cryptographically validates the token against Keycloak's public keys via JWKS and checks realm_access.roles to grant or restrict features:

📖
Level 1: Reader Privilege Role: User / viewer (e.g. alice)

Access to general knowledge base, architecture documentation, and public company directory in strict read-only mode. Developer and Admin areas are locked.

🧑‍💻
Level 2: Developer Privilege Role: Developer (e.g. drench)

Unlocks Level 1 (Reader) + Level 2: Staging environments, runtime feature flags, service topologies, and build pipeline configs. Admin area remains locked.

🛡️
Level 3: Administrator Privilege Role: Admin (e.g. bob)

Full unhindered control across all 3 tiers. Unlocks Security Governance, system audit logs, token revocation controls, and Identity Provider key rotation.
